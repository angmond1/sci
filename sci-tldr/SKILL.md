# sci-tldr — 논문 한국어 한 줄 요약 지침서

> 🐶 **리트리버 인사(정체성)**: 대화에서 아직 sci-retr·sci-index·sci-tldr 인사를 하지 않았으면 첫 줄은 *"안녕하세요 🐶 sci-tldr 가 논문을 한 줄로 요약할게요."* 한 줄, 그 다음부터는 평소 문체. 이어서 하는 작업이면 인사를 다시 하지 않는다. 작업 보고의 첫 줄은 머리표로 시작한다: `🐶 완료 — sci-tldr`(한줄요약을 다 채움) / `🐕 부분 완료 — sci-tldr`(보류·재료 없음이 남음, 예: 94/96) / `🐕‍🦺 중단 — sci-tldr`(막혀서 멈춤). `sci_tldr.py` 의 prep·apply 는 마지막 줄 끝에 `▼・ᴥ・▼` 를 찍는다. 한줄요약·`index.csv`·오류 문구에는 넣지 않는다.

## 1. 무엇을 하는가

- `sci-index` 가 만든 `index.csv` 에 **한줄요약** 열을 붙인다. 논문마다 한국어 한 문장(60~120자)으로 "무엇을 했고 무엇을 찾았는지"를 쓴다. 영어 제목·초록과 겹치지 않게 한국어로만 쓴다.
- 용도는 사람이 엑셀에서 한국어로 빠르게 훑는 것이다. LLM 이 논문 내용을 파악할 때는 초록과 본문(`source.md`)이 더 낫다. 한줄요약으로 본문 읽기를 대신하지 않는다.
- LLM 을 쓰는 곳은 이 skill 뿐이다(`sci-retr` 수집과 `sci-index` 색인은 LLM 없이 스크립트로 끝난다).

## 2. 언제 쓰나

- **사용자가 원할 때만.** 편수와 관계없다. 자동으로 돌리지 않는다.
- sci-retr 수집 → sci-index 색인이 끝나면 한 번 묻는다: "한국어 한 줄 요약도 만들까요? (N편, 약 M분)". 시간은 6절 실측으로 어림한다(묶음을 동시에 돌려 500편까지 대개 2분 안팎). 사용자가 나중에 "한 줄 요약 만들어줘" 라고 해도 쓴다.
- 먼저 `index.csv` 가 있어야 한다. 없으면 `sci_index.py build` 부터(몇 초).

## 3. 명령

스크립트는 `sci-retr` skill 폴더의 `scripts/sci_tldr.py` 다(`sci_index.py` 와 같은 폴더). 파이썬은 sci-retr skill 폴더의 `python.txt` 에 적힌 것을 쓴다.

```bash
python <sci-retr>/scripts/sci_tldr.py prep --kb-root <논문 폴더 root> [--ids <paper_id …>] [--body <paper_id …>] [--all]
```

```bash
python <sci-retr>/scripts/sci_tldr.py apply --kb-root <논문 폴더 root>
```

- `prep`: 한줄요약이 빈 행을 묶음 파일(`_collect/tldr_batch_<n>.md`)로 나눈다. 묶음마다 결과 파일 경로와 쓰는 규칙이 머리에 적혀 있고, 논문마다 제목·유형(review 등)·요약 재료 '글' 이 들어 있다. 재료는 초록(1,500자까지), 초록이 짧거나 없으면 본문 앞부분(이 논문 제목이 나오는 자리부터). 재료가 없는 논문은 넣지 않고 알린다(제목만으로 쓰면 지어내기 쉽다). 묶음 수는 편수(50편)·크기(50KB) 기준 중 큰 쪽으로 정하고 고르게 나눈다. 결과 번호는 이미 있는 결과 파일 다음부터라 덮어쓰지 않는다.
- `apply`: 결과(`_collect/tldr_*.jsonl`)를 검증해 한줄요약 열에 넣는다(6절 검증). 통과하지 못한 요약은 넣지 않고 '보류' 로 알린다. 한줄요약 쪽 판단(보류 사유, 제목-글 불일치 등)은 `index_check.csv` 에 `LLM:` 으로 붙는다. 같은 결과를 다시 합쳐도 겹치지 않는다.
- `--ids`: 보류된 논문이나 다시 받은 논문만 다시 묶는다. `--body`: 이 논문들은 본문 앞부분 3,000자를 재료로 다시 묶는다('재료 부족' 으로 비었는데 전문이 있는 논문, 예: 초록 칸이 배경 문단뿐인 논평). `--all`: 모든 행 다시.
- 초록만 받은 논문은 `source.md` 를 본문으로 쓰지 않는다(초록 보관 파일이다). 사이트 문구(All rights reserved 등)가 초록 칸에 들어온 것은 sci-index build 가 빼 두므로 재료가 되지 않는다.

## 4. 절차

1. `prep` 을 돌린다. 출력의 묶음 수와 '쓰기' 줄을 읽는다.
2. 쓰기:
   - **10편 미만**(보류 몇 편 다시 등): 하위 에이전트를 띄우지 않고 메인이 묶음 파일을 Read 로 한 번 읽고, 결과 JSONL 을 Write 로 한 번 쓴다. 하위 에이전트 하나에는 내용과 관계없는 고정 비용이 든다(6절).
   - **10편 이상**: 묶음마다 `sci-tldr-writer` 에이전트 하나를 동시에 띄운다. 프롬프트는 묶음 파일 경로 한 줄이면 된다: `묶음 파일: <root>/_collect/tldr_batch_<n>.md`. 이 에이전트는 도구 Read·Write 둘, 모델 sonnet, 추론 수준 low 로 정의되어 있다(설치 스크립트가 `~/.claude/agents/sci-tldr-writer.md` 로 복사).
   - `sci-tldr-writer` 가 없으면(설치 전 세션, 다른 환경) 메인이 묶음을 차례로 처리한다. 범용 에이전트는 쓰지 않는다(도구 설명이 많아 한 번 부를 때마다 약 7만 토큰이 더 든다, 2026-09-27 실측).
3. `apply` 를 돌린다. '보류' 가 있으면 `prep --ids <보류 id…>` 로 한 번 더 쓴다(대개 10편 미만이라 메인이 직접). '재료 부족' 으로 비었는데 원문상태가 전문이면 `prep --body <id…>` 로 한 번 더. 두 번째도 보류·비움이면 비워 두고 보고한다. 작성자가 비운 행은 예전 요약도 지운다.
4. 보고(5절).

## 5. 보고

사용자에게는 다음만 말한다.

- 한줄요약 채운 수 / 전체 (예: 94/96)
- 보류·비운 논문과 이유 한 줄씩 (재료 없음, 제목-글 불일치, 글에 없는 숫자 등)
- 걸린 시간

## 6. 할루시네이션 막기와 비용

요약에서 가장 흔한 잘못은 글에 없는 숫자, 바뀐 물질명·화학식, 제목만 보고 결과를 지어내는 것, 리뷰·논평을 자기 연구처럼 쓰는 것, 다른 논문의 글을 요약하는 것이다. 이렇게 막는다.

| 잘못 | 막는 방법 | 어디서 |
|---|---|---|
| 제목만 보고 결과를 지어냄 | 재료(초록·본문 앞부분)가 없으면 묶지 않는다 | prep |
| 다른 논문의 글을 요약 | 본문 앞부분을 이 논문 제목 자리부터 자른다(Cell Press Preview 는 첫 쪽이 앞 기사의 끝). 글이 제목과 다르면 비우고 '제목-글 불일치' | prep, 규칙 6 |
| 글에 없는 숫자·바뀐 숫자 | 요약의 숫자(두 자리 이상·소수)를 글과 대조한다. 영어 낱말로 쓴 수(ten times)는 숫자로도 대조한다. 소수점 아래를 버린 수는 통과 | apply |
| 바뀐 물질명·화학식 | 대문자로 시작하고 숫자가 든 토큰(Pd3Pb, MgFe2O4, H2O2)을 글과 대조한다 | apply |
| 배경지식·과장 | 글에 있는 내용만, '최초·최고' 는 글에 있을 때만 | 규칙 2·4 |
| 리뷰·논평을 연구처럼 | 묶음에 유형(review·editorial 등)을 적고 그렇게 쓰게 한다 | 규칙 5 |
| 판단 과정이 요약에 섞임 | "제공된 초록은 …" 같은 문구를 찾아 보류 | apply |

- 검증은 스크립트가 하므로 LLM 호출이 늘지 않는다. 2026-09-27 예전 요약 96편에 돌려 보니 걸린 것은 1편('more than ten times' → '10배', 낱말 수 대조를 넣어 해결)이었다. 지어낸 숫자(81.3 → 91.3)·화학식(Pd3Pb → Pt3Ni)은 시험에서 걸렸다.
- 한국어 낱말(용어 번역)은 대조하지 않는다. 숫자·화학식처럼 틀리면 해가 큰 것만 본다.

비용과 시간:

| 2026-09-27 같은 연습 코퍼스 | 범용 에이전트 (예전) | 전용 에이전트 `sci-tldr-writer` (지금) |
|---|---|---|
| 편수·묶음 | 96편, 34·29·33편 세 묶음 동시 | 95편, 35·30·30편 세 묶음 동시 |
| 시간 | 20.5분 (묶음별 10.8~20.5분) | 약 70초 (묶음별 65~73초, 새 세션 시작까지 85초) |
| 에이전트 첫 호출에 실리는 고정 내용 | 70,688 토큰 | 3,137 토큰 |
| 출력 (묶음당) | 4.8만~6.4만 토큰, 약 90% 가 보이지 않는 추론 | 5.1천~6.0천 토큰 |
| 처리 토큰 (캐시 포함, 에이전트 합) | 약 133만 | 약 16.2만 (한 편 약 1.7천) |
| 결과 | 96/96 (검증 없음) | 검증 통과 90, 길이 초과 보류 3 → 메인이 다시 써 통과, 재료 부족 2(사이트 문구 초록 1은 색인에서 뺌, 논평 1은 `--body` 로 다시 써 통과) |

- 차이의 이유: 범용 에이전트는 모든 도구 설명을 싣고(호출마다 다시 읽음) 추론 수준을 따로 정하지 않아 요약 한 줄에 긴 추론을 했다. 전용 에이전트는 도구를 Read·Write 둘로, 추론 수준을 low 로 정했다. 묶음 파일도 요약에 필요한 것(제목·유형·글)만 담는다.
- 요약 품질은 예전과 비슷했고(예전 요약과 나란히 비교), 숫자는 모두 글과 맞았다. 길이 중앙값 98자.
- 새 에이전트 정의는 새 대화(세션)부터 인식된다. 설치 직후 같은 대화에서는 메인이 묶음을 처리한다(4절).

## 7. 파일 위치

```
<root>/
  index.csv                   색인 — 한줄요약 열을 이 skill 이 붙인다
  index_check.csv             검수 flag — 한줄요약 쪽 판단은 'LLM:' 으로
  _collect/tldr_batch_<n>.md  한줄요약 묶음 (prep)
  _collect/tldr_src_<n>.json  묶음에 넣은 요약 재료 글 (apply 가 대조에 쓴다)
  _collect/tldr_<n>.jsonl     에이전트가 쓴 결과
```

## 8. 하지 않는 것

- 사용자가 원하지 않았는데 한줄요약을 만드는 것. 편수로 자동 실행하지 않는다.
- 재료 없이 제목만으로 요약하는 것.
- 범용 에이전트로 요약하는 것(비용이 크다).
- 한줄요약만 보고 본문 읽기를 건너뛰라는 규칙. 한줄요약은 고르기·훑기용이다.
